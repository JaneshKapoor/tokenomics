# Tokenomics MCP Server

A custom **MCP server** that exposes AI cost / token-usage data — spend by team,
by agent, top expensive requests, model mix, and anomaly flags — as structured
tools. Register it into Archestra's private MCP registry, then build the actual
cost dashboard by **prompting Archestra's chat** against these tools (see
[Building the dashboard in Archestra](#building-the-dashboard-in-archestra)).

The server is the data layer. It does **not** ship a UI — that's generated by
Archestra from a prompt.

---

## What it provides

Seven tools, all returning compact JSON meant to be consumed by an LLM:

| Tool | Args | Returns |
| --- | --- | --- |
| `get_spend_summary` | `start_date`, `end_date`, `group_by: day\|week` | `[{ date, total_cost_usd, total_tokens, prompt_tokens, completion_tokens }]` |
| `get_spend_by_team` | `start_date`, `end_date` | `[{ team, total_cost_usd, total_tokens }]` |
| `get_spend_by_agent` | `start_date`, `end_date` | `[{ agent_name, total_cost_usd, total_tokens, request_count }]` |
| `get_top_expensive_requests` | `start_date`, `end_date`, `limit` | `[{ timestamp, agent_name, model, cost_usd, prompt_preview, prompt_tokens, completion_tokens }]` |
| `get_model_mix` | `start_date`, `end_date` | `[{ model, request_count, total_cost_usd, pct_of_total }]` |
| `get_spend_anomalies` | `threshold_multiplier` (default 2.0) | `[{ agent_name, date, spend_usd, seven_day_avg_usd, ratio }]` |
| `get_cost_optimizer_savings_estimate` | `cheap_model_threshold_tokens` (default 1000) | `{ current_cost_usd, estimated_savings_usd, pct_savings, assumption }` |

`prompt_preview` is only the first ~100 chars of a prompt — never the full text.

## Data sources

Selected by the `TOKENOMICS_DATA_SOURCE` env var. Both implement the same
`DataSource` interface, so every tool is source-agnostic.

### `synthetic` (default)

Zero external dependencies. Generates ~14 days of deterministic-but-randomized
usage on start:

- 5 fictional agents across 5 fictional teams (Team Nebula, Falcon, Orbit,
  Quasar, Pulsar). All names invented.
- 3 models spanning a cheap / mid / expensive price tier (`claude-haiku-4-5`,
  `claude-sonnet-5`, `claude-opus-4-8`) — fictional rates in `src/pricing.ts`.
- Weekend dips, and a deliberate **~6× spend spike** on `clustering-monitor`
  (4 days before the end of the window) so `get_spend_anomalies` has a real
  signal to flag.

Dates are anchored to *today* so the demo always looks current; values are
produced by a seeded PRNG keyed on `(date, agent, index)`, so a given calendar
day always yields the same numbers.

### `prometheus` (stretch — implemented, not yet verified live)

Reads Archestra's LLM observability metrics via the standard Prometheus HTTP
API (`/api/v1/query_range`), querying `llm_cost_total` and `llm_tokens_total`
grouped by agent / model / source labels.

> ⚠️ **Status:** implemented against the documented Prometheus HTTP API, but
> **not verified against a live Archestra instance** (no reachable endpoint was
> available at build time). Metric/label names that might differ per deployment
> are all configurable via env (see below) so it can be adapted without code
> changes. `agent_name` and `source` labels are confirmed from Archestra docs;
> a `team` label and a token-type label are **not** confirmed — verify before
> relying on `get_spend_by_team` against real data.
>
> Because Prometheus stores aggregated counters (not individual requests), this
> source emits one record per `(day, agent, model)` bucket. Aggregating tools
> are exact; `get_top_expensive_requests` becomes "most expensive bucket" and
> `prompt_preview` is empty (Prometheus holds no prompt text).

## Environment variables

| Var | Default | Purpose |
| --- | --- | --- |
| `TOKENOMICS_DATA_SOURCE` | `synthetic` | `synthetic` or `prometheus` |
| `PROMETHEUS_URL` | — | Base URL of Prometheus (required when source is `prometheus`) |
| `TOKENOMICS_AGENT_LABEL` | `agent_name` | Prometheus label for the agent |
| `TOKENOMICS_MODEL_LABEL` | `model` | Prometheus label for the model |
| `TOKENOMICS_SOURCE_LABEL` | `source` | Prometheus label for the source |
| `TOKENOMICS_TEAM_LABEL` | `team` | Prometheus label for the team (falls back to source) |
| `TOKENOMICS_TOKENTYPE_LABEL` | `type` | Label distinguishing prompt vs completion tokens |
| `TOKENOMICS_COST_METRIC` | `llm_cost_total` | Cost counter metric name |
| `TOKENOMICS_TOKENS_METRIC` | `llm_tokens_total` | Tokens counter metric name |

## Run it locally

### With Node

```bash
npm install
npm run build
node dist/index.js          # speaks MCP JSON-RPC over stdio
```

Smoke-test the MCP surface (initialize → tools/list → tools/call):

```bash
npm run smoke                # -> node dist/index.js
```

Inspect every tool's output against the synthetic data:

```bash
npm run test:tools
```

### With Docker

```bash
npm run docker:build         # docker build -t tokenomics-mcp .
docker run -i --rm -e TOKENOMICS_DATA_SOURCE=synthetic tokenomics-mcp

# verify the container speaks MCP:
npm run smoke:docker
```

The server communicates over **stdio** — always run the container with `-i`.

## Register in Archestra's private MCP registry

Archestra runs added MCP servers as sibling Docker containers (its local
quickstart mounts the host Docker socket), so registration is the standard
`docker run -i --rm` stdio pattern used by most catalog entries.

1. **Build the image** so Archestra can run it:
   ```bash
   docker build -t tokenomics-mcp .
   ```
2. In the Archestra web UI (default `http://localhost:3000`), open
   **Settings → MCP servers / registry → Add server** (exact wording varies by
   Archestra version — look for the private/custom MCP registry section).
3. Add it as a **command / stdio** server with:
   - **Command:** `docker`
   - **Args:** `run -i --rm -e TOKENOMICS_DATA_SOURCE=synthetic tokenomics-mcp`

   Or, as MCP server config JSON:
   ```json
   {
     "mcpServers": {
       "tokenomics": {
         "command": "docker",
         "args": ["run", "-i", "--rm", "-e", "TOKENOMICS_DATA_SOURCE=synthetic", "tokenomics-mcp"]
       }
     }
   }
   ```
4. Save/enable the server. Archestra should list the 7 `tokenomics` tools once
   it connects. If it doesn't appear, confirm the image name resolves inside
   Archestra's environment and that Docker socket access is available.

To point at live Archestra metrics instead, swap the env in the args:
`-e TOKENOMICS_DATA_SOURCE=prometheus -e PROMETHEUS_URL=http://<prometheus>:9090`.

## Building the dashboard in Archestra

Once the tools are registered, describe the dashboard in Archestra's chat — for
example:

> Using the `tokenomics` tools, build me an AI-spend dashboard for the last 14
> days. Show total spend and token usage over time (`get_spend_summary`), a
> breakdown by team and by agent, the model mix as a share of cost, the top 10
> most expensive requests, and a panel that flags any spend anomalies. Add a
> "potential savings" callout from `get_cost_optimizer_savings_estimate`.
